# Аномалии в review.csv

## Главный вывод

`review.csv`, судя по всему, **не относится к тому же датасету компаний**, что и `page_*.json`: 97% записей (199 из 205) ссылаются на `external_id`, которых нет в исходной выгрузке компаний, а 193 записи вообще выходят за пределы диапазона ID `c_000001`–`c_001000`. Это похоже на то, что файл был перепутан или это выгрузка для другого проекта/периода. Детальный список остальных 36 более мелких аномалий (форматирование, пустые поля, дубли) — ниже.

---

Данные загружены скриптом `db/load-reviews.ts` в таблицу `reviews`.
В файле 207 строк данных + заголовок; 2 строки в конце пустые (пропущены при загрузке).
**Итого в БД: 205 записей.** Ниже — каждая находка отдельным пунктом, без «тихого» исправления.

> **Примечание:** колонки `email` в CSV **нет** — проверка email выполнялась по паттерну `@` во всех текстовых полях (`phone`, `website`, `name`); совпадений **0**.

---

## 1. ID компаний отсутствуют в исходном датасете page_*.json

**(a) Проблема:** `external_id` из CSV не найден в таблице `companies` (загружена из `page_001.json` … `page_020.json`, диапазон `c_000001`–`c_001000`).

**(b) Как обнаружил:**
```sql
SELECT COUNT(*) FROM reviews r
LEFT JOIN companies c ON r.external_id = c.external_id
WHERE c.external_id IS NULL;
```

**(c) Затронуто записей:** **199**

---

## 2. ID выходят за пределы диапазона JSON (c_001001+)

**(a) Проблема:** идентификаторы больше `c_001000` — таких компаний нет в `page_*.json` (total=1000, id до `c_001000`).

**(b) Как обнаружил:**
```sql
SELECT COUNT(*) FROM reviews WHERE external_id > 'c_001000';
```

**(c) Затронуто записей:** **193** (199 минус 6 тестовых `c_900xxx`)

---

## 3. Тестовые / синтетические ID (c_900006–c_900011)

**(a) Проблема:** ID с префиксом `900` не встречаются в JSON; похоже на искусственные записи.

**(b) Как обнаружил:**
```sql
SELECT external_id, name FROM reviews
WHERE external_id LIKE 'c_900%' ORDER BY external_id;
```
Примеры: `c_900006` (АО Орион Групп), `c_900008` (АО Флагман Лаб).

**(c) Затронуто записей:** **6**

---

## 4. Дублирующиеся external_id в CSV

**(a) Проблема:** одни и те же ID встречаются дважды с идентичным содержимым — copy-paste при экспорте.

**(b) Как обнаружил:**
```sql
SELECT external_id, COUNT(*) FROM reviews
GROUP BY external_id HAVING COUNT(*) > 1;
-- c_001049, c_001050, c_001075
```
Визуально: строки 42/204, 117/205, 7/206 в `data_pack/review.csv`.

**(c) Затронуто записей:** **6** (3 уникальных ID × 2 вхождения)

## 5. Пустые строки в конце файла

**(a) Проблема:** строки 207–208 содержат только запятые, без данных.

**(b) Как обнаружил:** визуальный осмотр `data_pack/review.csv`; лог `load-reviews.ts`: «Пустых строк пропущено: 2».

**(c) Затронуто записей:** **2** (не загружены в БД)

## 6. Пустой рейтинг (rating)

**(a) Проблема:** поле `rating` пустое; в схеме `companies` это `NUMERIC(3,1)`, допускается `NULL`, но не пустая строка.

**(b) Как обнаружил:**
```sql
SELECT COUNT(*) FROM reviews WHERE COALESCE(rating, '') = '';
```

**(c) Затронуто записей:** **18**

---

## 7. Рейтинг = N/A (текст вместо числа)

**(a) Проблема:** значение `N/A` не приводится к `NUMERIC`.

**(b) Как обнаружил:**
```sql
SELECT external_id, rating FROM reviews WHERE rating = 'N/A';
-- c_001083
```

**(c) Затронуто записей:** **1**

---

## 8. Отрицательный рейтинг

**(a) Проблема:** `rating = -3` — вне допустимого диапазона 0–5.

**(b) Как обнаружил:**
```sql
SELECT external_id, rating FROM reviews WHERE rating ~ '^-';
-- c_001122
```

**(c) Затронуто записей:** **1**

---

## 9. Рейтинг выше 5

**(a) Проблема:** `rating = 7.2` — невозможное значение для 5-балльной шкалы.

**(b) Как обнаружил:**
```sql
SELECT external_id, rating FROM reviews
WHERE rating ~ '^[0-9]' AND replace(rating, ',', '.')::numeric > 5;
-- c_001186
```

**(c) Затронуто записей:** **1**

## 10. Рейтинг с запятой вместо точки

**(b) Как обнаружил:**

**(c) Затронуто записей:** **1**

## 17. Телефон без формата +7 (XXX)

**(a) Проблема:** номер начинается с `8 (` вместо `+7 (` — несовместимо с нормализацией в `load.ts`.

**(b) Как обнаружил:**
```sql

WHERE phone <> '' AND phone !~ '^\+7 \(' AND phone !~ '^8 \(';
-- пусто; дополнительно:
SELECT external_id, phone FROM reviews WHERE phone LIKE '8 (%';
-- c_001004 (совпадает с п.15)
```

**(c) Затронуто записей:** **1** (та же запись `c_001004`)

## 19. Mojibake (битая кодировка) в name и city

## 35. Несоответствие типов данных схеме companies

**(a) Проблема:** в `reviews` все поля — `VARCHAR`; в `companies` — `NUMERIC`, `INTEGER`. При загрузке 22 записи с `rating` не приводятся к числу, 3 — `reviews_count` не приводятся к integer (см. п.6–13).

**(b) Как обнаружил:** сравнение `db/schema.sql` (companies vs reviews); попытка cast:
```sql
SELECT COUNT(*) FROM reviews
WHERE COALESCE(rating,'') <> '' AND rating !~ '^-?[0-9]+([.,][0-9]+)?$';
-- 1 (N/A)
```

**(c) Затронуто записей:** **25** (22 rating + 3 reviews_count, без пересечений)

## 37. Несоответствие формата JSON (системное)

**(a) Проблема:** CSV и JSON описывают один продукт, но CSV — «грязная» выгрузка:
- JSON: `rating` — number; CSV — строки с `N/A`, запятыми, минусом
- JSON: ID `c_000001`–`c_001000`; CSV: преимущественно `c_001001+` и `c_900xxx`
- JSON: `name` с «ёлочками»; CSV: mojibake, CSV-кавычки

**(b) Как обнаружил:** сравнение `page_001.json` (вывод `npm run load`) с `review.csv`; SQL из пунктов 1–2.

**(c) Затронуто записей:** **205** (весь файл)
