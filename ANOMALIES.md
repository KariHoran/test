# Аномалии в review.csv

Данные загружены скриптом `db/load-reviews.ts` в таблицу `reviews` (205 строк, 2 пустые строки в конце файла пропущены). Ниже — находки без «тихого» исправления.

---

## 1. ID компаний вне основного датасета (c_000001–c_001000)

**Что:** 199 из 205 записей ссылаются на `external_id`, которых нет в таблице `companies` (загружена из `page_*.json`).

**Как обнаружил:**
```sql
SELECT COUNT(*) FROM reviews r
LEFT JOIN companies c ON r.external_id = c.external_id
WHERE r.external_id IS NOT NULL AND c.external_id IS NULL;
-- результат: 199

SELECT
  COUNT(*) FILTER (WHERE external_id <= 'c_001000' AND external_id ~ '^c_00[0-9]{4}$') AS in_range,
  COUNT(*) FILTER (WHERE external_id > 'c_001000' OR external_id LIKE 'c_900%') AS out_of_range
FROM reviews;
-- in_range: 6, out_of_range: 199
```

**Почему подозрительно:** `review.csv` выглядит как «отзывы/компании», но почти не пересекается с основным каталогом из JSON. Большинство ID — диапазон `c_001001+` и тестовые `c_900xxx`, тогда как JSON содержит только `c_000001`–`c_001000`.

---

## 2. Тестовые / фиктивные ID (c_900006–c_900011)

**Что:** 6 записей с ID вида `c_90000x`, явно отличающимся от основной нумерации.

**Как обнаружил:**
```sql
SELECT external_id FROM reviews WHERE external_id LIKE 'c_900%' ORDER BY external_id;
```

**Примеры:** `c_900006` (АО Орион Групп), `c_900008` (АО Флагман Лаб), `c_900011` (АО Сокол Лаб).

**Почему подозрительно:** префикс `900` не встречается в `page_*.json`; похоже на синтетические записи для тестирования.

---

## 3. Дублирующиеся строки в CSV

**Что:** 3 `external_id` встречаются дважды: `c_001049`, `c_001050`, `c_001075`.

**Как обнаружил:**
```sql
SELECT external_id, COUNT(*) FROM reviews
WHERE external_id IS NOT NULL
GROUP BY external_id HAVING COUNT(*) > 1;
```

**Почему подозрительно:** полные дубликаты строк (визуальный осмотр строк 42/204, 117/205, 7/206 в CSV) — вероятная ошибка экспорта или copy-paste.

---

## 4. Пустые строки в конце файла

**Что:** строки 207–208 файла содержат только запятые (все поля пустые).

**Как обнаружил:** визуальный осмотр `data_pack/review.csv`; скрипт загрузки залогировал «Пустых строк пропущено: 2».

**Почему подозрительно:** мусор в конце файла, может ломать парсеры без фильтрации.

---

## 5. Невалидные значения рейтинга

**Что:** в поле `rating` встречаются нечисловые или невозможные значения.

| Значение | Кол-во | Пример ID |
|----------|--------|-----------|
| `N/A`    | 1      | c_001083  |
| `-3`     | 1      | c_001122  |
| `7.2`    | 1      | c_001186  |
| `4,5`    | 1      | c_001010  |
| пусто    | 18     | —         |

**Как обнаружил:**
```sql
SELECT rating, COUNT(*) FROM reviews
WHERE rating IN ('N/A', '-3', '7.2', '4,5', '') OR rating IS NULL
GROUP BY rating;
```

**Почему подозрительно:** рейтинг обычно 0–5; `-3` и `7.2` — явные ошибки; `4,5` — запятая вместо точки (локаль/ручной ввод); `N/A` — текст вместо числа.

---

## 6. Невалидные значения reviews_count

**Что:**
- `c_001116`: `reviews_count = -10` (отрицательное число)
- `c_001079`: `reviews_count = 45.5` (дробное)
- `c_001187`: `reviews_count = много` (текст)

**Как обнаружил:**
```sql
SELECT reviews_count, COUNT(*) FROM reviews
WHERE reviews_count ~ '[^0-9.-]' OR reviews_count LIKE '%.%'
GROUP BY reviews_count;

SELECT external_id, reviews_count FROM reviews WHERE reviews_count ~ '^-';
```

**Почему подозрительно:** счётчик отзывов должен быть целым неотрицательным числом.

---

## 7. Невалидные / подозрительные телефоны

**Что:**
- `c_001004`: `8 (925) abc-12-34` — буквы в номере
- `c_001091`: `+7` — неполный номер
- 20 записей с пустым телефоном

**Как обнаружил:**
```sql
SELECT phone, COUNT(*) FROM reviews
WHERE phone IS NULL OR phone = '' OR phone !~ '^\+7' OR phone ~ '[a-zA-Z]'
GROUP BY phone;
```

**Почему подозрительно:** телефон не может содержать `abc`; `+7` без цифр — явный мусор.

---

## 8. Битая кодировка (mojibake) в name и city

**Что:** 2 записи с кракозябрами вместо кириллицы:
- `c_001008`: name = `РћРћРћ В«Р—Р°СЂСЏ РўРµС…В»`, city = `РњРѕСЃРєРІР°`
- `c_001128`: name = `РћРћРћ В«РўРµРјРї РњРµРґРёР°В»`, city = `РЎР°РЅРєС‚-РџРµС‚РµСЂР±СѓСЂРі`

**Как обнаружил:** визуальный осмотр CSV; SQL:
```sql
SELECT external_id, name, city FROM reviews WHERE name LIKE '%Рћ%';
```

**Почему подозрительно:** UTF-8 текст был прочитан как Latin-1/Windows-1252 (классический mojibake). Остальные поля (адрес) в тех же строках — нормальная кириллица.

---

## 9. Опечатки и несогласованность в названиях городов

**Что:**
- `c_001182`: город `Санкат-Петербург` (опечатка)
- `c_001108`: город `Moscow` (латиница вместо «Москва»)
- `c_001047`: город `москва` (строчные буквы)

**Как обнаружил:**
```sql
SELECT city, COUNT(*) FROM reviews
WHERE city ILIKE '%moscow%' OR city ILIKE '%санкат%' OR city = 'москва'
GROUP BY city;
```

**Почему подозрительно:** в JSON все города на русском с заглавной буквы; смешение языков и регистра ломает фильтрацию.

## 10. Сдвиг колонок (нарушена структура строки)

**Что:** `c_001015` — в поле `category` стоит `Пермь`, а `city` = `ул. Советская, д. 89, офис 43` (это адрес).

**Как обнаружил:** визуальный осмотр строки 37 CSV; SQL:
```sql
SELECT external_id, name, category, city FROM reviews
WHERE category NOT IN (SELECT DISTINCT category FROM companies WHERE category IS NOT NULL)
  AND category IS NOT NULL LIMIT 5;
```

**Почему подозрительно:** пропущено поле или лишняя запятая сдвинула category→city, city→address. Структура не соответствует заголовку CSV и JSON.

---

## 11. Невалидные / мусорные URL сайтов

**Что:**
- `c_001132`: `https://` (пустой домен)
- `c_001064`: `нет сайта` (текст вместо URL)
- `c_001020`: `htp://sintez-service-453.ru` (опечатка протокола)
- `c_001135`, `c_001088`: оба используют один URL `https://shared-site.ru`

**Как обнаружил:**
```sql
SELECT website, COUNT(*) FROM reviews
WHERE website IN ('https://', 'нет сайта') OR website LIKE 'htp:%'
GROUP BY website;

SELECT COUNT(*) FROM reviews WHERE website = 'https://shared-site.ru';
-- 2
```

**Почему подозрительно:** placeholder-значения и общий «shared-site» для разных компаний выглядят как заглушки.

## 14. Пустые обязательные поля

**Что:** 18 записей без рейтинга, 20 без телефона, несколько без сайта (пустая строка, не `null`).

**Как обнаружил:** агрегации по пустым полям при загрузке и SQL `WHERE phone IS NULL OR phone = ''`.

**Почему подозрительно:** для B2B-каталога phone/site часто обязательны; массовые пропуски могут указывать на неполный экспорт.

---

## 15. Несоответствие формата JSON

**Что:** CSV использует ключ `site`, как и JSON, но:
- JSON: `rating` — number | null; CSV: строки `"4,5"`, `N/A`, пусто
- JSON: стабильные ID `c_000xxx`; CSV: в основном `c_001xxx+` вне диапазона JSON
- JSON: `name` с «ёлочками» `«»`; CSV: иногда без ООО/кавычек или с mojibake

**Как обнаружил:** сравнение `page_001.json` (пример записи при `npm run load`) с полями `review.csv`.

**Почему подозрительно:** файлы выглядят как один продукт, но CSV — «грязная» выгрузка с другого источника или этапа пайплайна.
